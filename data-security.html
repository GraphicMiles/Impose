Know where your data goes.

Impose is local-first, not local-only. This page maps browser storage, direct providers, relay tools, analytics, exports, and the controls attached to each path.

Browser storage

Impose stores its working state in local storage so it can reopen without a server-side chat database. This can include sensitive content and credentials. Anyone with access to your unlocked browser profile may be able to access that data.

Clearing site data removes the local workspace. Standard chat exports exclude provider API keys.

Model providers

Direct mode sends requests from your browser to the endpoint you configure. The endpoint receives the provider credential and request content. Provider model-list and probe actions also contact the endpoint.

Provider policies determine whether prompts and outputs are logged, retained, or used for service improvement. Review those policies before sending confidential data.

Relay, proxy, and research tools

The default public relay offers rate-limited search and image search. Protected relay features require a control key. The generic fetch proxy can forward model requests to providers that block browsers, which means that relay can see forwarded credentials and content.

Depending on availability and configuration, requests may reach SearXNG, Bing, DuckDuckGo, Openverse, Wikimedia Commons, Wikipedia, Tavily, Brave Search, or Serper. Each service applies its own terms and data practices.

Relay protections include IP-based rate limits, constant-time key comparison, public-host-only fetch targets, resolved-IP checks, blocked redirects, response-size limits, and request timeouts. In-memory search, image, and page-read caches expire after roughly two to five minutes.

Analytics and hosting

The main application loads Cloudflare Web Analytics. The site and relay run on hosting infrastructure that may produce access, performance, and security logs. Query strings can appear in access logs when a request places a search term in the URL.

Exports and encryption

Plain chat exports contain chats and folders, not provider or relay keys. Encrypted backups use AES-GCM with a 256-bit key derived in the browser using PBKDF2-SHA-256, a random salt, and a random initialization vector.

Encrypted backup passphrases are not stored or recoverable. Losing the passphrase means losing access to that backup.

Controls you can use

  • Delete one chat or all chats.
  • Remove provider and relay credentials.
  • Set a retention window while preserving pinned chats.
  • Enable PII redaction before sending prompts.
  • Export chats and create passphrase-encrypted backups.
  • Use demo mode or direct providers instead of the public relay.
  • Inspect and approve browser actions before consequential sends.

Security limits

No web application, browser profile, model provider, or relay is risk-free. Impose does not provide end-to-end encryption for live provider requests. Browser storage is not a secure vault. PII redaction is pattern based and may miss sensitive information.

Use separate, limited-scope keys where providers support them. Revoke exposed credentials, secure your device, and avoid sending secrets that are not necessary for the task.
