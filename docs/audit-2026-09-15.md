## Failure modes found and fixed

Each fix is at the shared primitive, not at the call site that happened to notice.

1. **A policy verdict could replace the user's goal and end the turn** (P1).
   The semantic intent step returns a decomposition. Some conversational models answer a legality or safety question inside `goal` and return no requirements. `normalizeIntent` synthesized a subgoal from that verdict, the planner selected `reasoning.synthesize`, and the app composed a refusal without consulting a single provider. The relay would have answered honestly: package requests route through ranked provider metadata, and the catalog carries `google-play` and `apkmirror` (`official_marketplace`, `reputable_distribution`) whose legitimate outcome is an attributed `accessMode: open` action, not a file.
   Fixed in `agent/orchestrator.js`: the interpreter prompt now states that judging legality, safety, licensing, or permission is out of scope for decomposition, and `normalizeIntent` rejects a refusal-shaped goal that carries neither requirements nor a clarification. Rejection feeds the existing one bounded repair, then the caller's fallback, which asks the answer model. Policy stays with the answer model and its provider; attribution of a refusal becomes honest.
   Regression: `agent/tests/audit-regressions.js`.

2. **Provider keys leaked into the copyable debug log** (P1, privacy).
   `sanitizeUrl` masked exactly five spellings (`key`, `api_key`, `token`, `auth`, `secret`). The app supports a query-parameter key **named anything** the user chooses, and `fetch` is instrumented to log every URL, so `?apikey=`, `?subscription-key=`, `?access-token=`, `?password=`, and any custom name were written out verbatim. URL userinfo was also logged.
   Fixed in `app.js`: redaction is now by name shape (key, token, secret, password, credential, authorization, bearer, signature, api key variants), plus exact short names (`sig`, `auth`, `code`, `otp`, `token`) matched as whole parameters so `design=` and `assign=` stay readable, plus userinfo masking.
   Regression: `agent/tests/audit-regressions.js`.

3. **A side effect needed no proof that the user approved it** (P0 in the agent invariant, P1 as shipped).
   The exactly-once rule lived only in the page: `/approve` consumed `impose.browser-plan.v1` and re-checked the plan id. `extension/background.js` routed `x.post`, `x.reply`, and `dm.send` from caller-supplied `params` with nothing to verify, so a replay, a duplicate tab event, or a client bug could publish twice on the user's behalf with no boundary refusing it.
   Fixed at the trust boundary: the client mints a single-use token from the consumed approval (`chatId:planId:startedAt:actionSeq`) and the worker claims it before dispatch, serialized so two concurrent claims cannot both read "unspent". A replay returns "That approval was already spent. Nothing was sent a second time." The manual two-tap send path in the panel mints its own token from the arm tap, so the human authorization is what authorizes, in both flows.
   Regression: `agent/tests/audit-regressions.js`.

4. **The capability pipeline returned a row for `limit: 0`** (P2).
   The bound was tested after appending, so a caller asking for nothing received the top candidate. Fixed in `backend/relay/capabilities.py` by testing the bound first.
   Regression: `backend/relay/tests/test_capabilities.py`.

5. **Engine parsers threw on well-formed-but-wrong replies** (P2).
   `parse_searxng` iterated whatever `results` held, so `{"results": "text"}` or scalar rows raised `AttributeError`. The job wrapper contained it, so it degraded rather than failing the request, but one odd reply cost the whole provider. Fixed to skip non-object rows and non-mapping payloads.
   Regression: `backend/relay/tests/test_search.py`.

6. **Provider discovery accepted hostnames from non-URLs** (P3).
   `ProviderCatalog.discover` trusted any string: `//x` parses to host `x` and registered a provider nobody asked for. Fixed to require an absolute `http`/`https` URL.
   Regression: `backend/relay/tests/test_source_intelligence.py`.

7. **`escapeHtml` left apostrophes live** (P3, latent).
   Every current interpolation lands in a double-quoted attribute, so nothing was exploitable, but a single-quoted attribute added later would be an injection point. Now escaped.

8. **House rules and stale build state** (P2 for the build, P3 for copy).
   `impose-standalone.html` was 200 insertions behind its own sources, was not copied by the Render build, and nothing detected the drift. `build_inline.py --check` now fails on drift, the Blueprint ships the artifact, and a GitHub Actions workflow runs every suite plus the scenario matrix. Three user-visible strings and one comment used em dashes, which the README forbids.

## Assumptions recorded before testing

- A refusal is a provider and answer-model decision, not a routing decision. The intent layer is a compiler; it may report risk, low confidence, or a clarification, and must not silently decide for the user.
- The Impose origin is the extension's trust boundary. The worker cannot distinguish application code from a page script running on that origin, so it enforces what it can verify: origin pairing inputs, single-use approval tokens, and destination path refusal. Anything stronger needs a server-side gate, which is out of scope here.
- `null` from `_semantic_bool` means "not specified", not "false", so it is a valid normalization result and is not counted as a defect.
- Rejecting a passphrase under eight characters is the documented contract of `encryptExport`, so it is a pass.

## Verified, not assumed

- Malformed request bodies across the relay's four capability endpoints return 400 or 200, never 5xx, for scalar, boolean, list, object, and JSON-string shapes (live probe through `TestClient`).
- Identical intents produce byte-identical source plans across 260 randomized requirement shapes; no candidate list is ever re-ordered or duplicated.
- The claim pipeline never returns a candidate missing a required claim, across 200 randomized claim sets, with one adapter raising to confirm provider failures stay independent.
- Approval replay, duplicate arm taps, and unapproved side effects are all refused.

## Remaining risks, accepted

1. **Intent quality depends on the chat model.** A weaker model can still return a decomposition with wrong capabilities. Mitigated by the registry (unknown capability ids resolve to a provider's primary capability, then to `blocked`), never by guessing from user wording.
2. **Client-side state remains the approval ledger for browsing.** The token makes a side effect exactly-once, but a compromised origin can still mint one; the extension cannot see intent beyond what the page reports.
3. **The public tier costs are bounded but real.** `/v1/image-convert` remains 60 requests/minute/IP on free-tier CPU with an unbounded-lifetime HMAC.
4. **No persistence for the performance ledger or the rate buckets.** Cold starts reset adaptive ranking; `_RATE_BUCKETS` never evicts keys, so a very long-lived process grows slowly with unique IPs.
5. **The auth screens remain non-functional by design.** No backend exists behind sign-in, OTP, or reset.
6. **Mobile and real-browser behavior is untested here.** The sandbox has no browser; DOM, layout, touch, and extension-install lifecycles are exercised only at the module level. Scenario classes covering viewport, tab churn, and gesture races are written as state-machine models, not as Playwright runs.
7. **Wiring a real model into the intent step was out of scope.** No scenario in this audit proves that a specific hosted model never returns a verdict-shaped goal; the guard makes such a return loud and recoverable rather than silent.
